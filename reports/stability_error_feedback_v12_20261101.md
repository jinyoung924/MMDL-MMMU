# 취약 문항의 실패 단계와 오류 교정 학습

**새 오류 교정 SFT도 이번 고정 DEV 평가에서 성능 향상에 실패했다.** 취약12의 정답 수는 기본 모델8개, A 재풀이2개, B 교정+재풀이6개였다. 안정12에서도 A는2개, B는1개를 새로 틀렸다. 두 군 모두 사전 기준에 실패해 추가 학습·추가 생성 시드 평가는 실행하지 않는다.

기존120응답 검수, TRAIN 라벨 검수, 새 A/B 각30스텝 학습과 독립 학습·평가 감사, 새 후보48응답의 익명 풀이 검수를 모두 완료했다. 과거 실험의 성공 기준이나 후보도 다시 선택하지 않는다.

같은 문항·같은 생성 시드16의 대응 비교다. 24개 원문 그림과 문제를 먼저 독립적으로 풀고 모두 봉인한 뒤, 모델명·정오답을 가린 응답120개를 전부 읽었다. 원문24개 독립 정답은 기존 정답표와 모두 일치했고, 판정 근거230개 인용의 정확한 원문 일치를 확인했다. 문제마다 한 명의 Terra 6.1 max 검수자가 판정했으며 사람 검증이나 형식 증명 인증은 아니다.

길이 제한 응답의 최종 논증은 미확인으로 유지했다. 중간의 잘못된 주장을 명시적으로 고쳤거나, 잘못된 부가 설명과 별개로 충분한 최종 논증을 제시한 경우를 전체 응답 무오류와 구분했다.

## 관측된 실패 위치

기본 모델의 취약12에서 처음 남은 오류는 그림 사실5·관계 연결1, 판정 불가1, 타당한 최종 풀이5였다. 길이 제한 응답도 실제 확인한 앞부분 오류의 위치는 기록할 수 있지만 최종 풀이를 확정하지 않는다. 그림 사실과 관계 연결은 출력상의 분류이며 시각 인코더 자체의 고장을 뜻하지 않는다.

올바른 풀이 뒤 선택지 글자만 틀린 순수 매핑 오류는 이번120응답 검수에서 확인되지 않았다. 전체 LoRA30의 취약12에서는 선택지 대조 실패도9개 표시됐지만, 앞선 그림·정리·계산 오류와 겹치므로 순수 매핑 실패9개라고 해석하지 않는다.

MLP 동결5에서는1538의 기존 정답 글자는 유지되면서 최종 논증이 무효에서 유효로 바뀐 판정이 있다. 다른 응답의 회귀·미완료도 함께 남아 있으므로 이 국소 회복을 전체 성능 향상으로 바꾸어 말하지 않는다. 전체 LoRA30과 MLP 동결30은 기본 모델의 유효 풀이1912·2055·541·908을 각각 무효로 바꿨다는 판정이다.

문항별 단계와 회복·회귀는 [120응답 대응 결과](../pilot_diagram/stability_v1/error_feedback_v12_20261101/descriptive_error_stage_results.json)에, 원문 도형·목표 종류별 집계는 [기하 세부 유형](../pilot_diagram/stability_v1/error_feedback_v12_20261101/source_subtype_error_breakdown.json)에 보존했다. 현재 표본은 기하의 고정 취약12·안정12이며 다른 분야의 오류 비율을 대표하지 않는다.

## TRAIN 교정 자료

기존 원래 TRAIN24의 기본 모델 선별 응답에서 승인 정답 기준 처음 틀린 시드0–4를 문항별로 고정했다. 원문 그림, 정확한 학생 오류 구간, 오류 이유, 수정 지시와 정답 풀이를 연결했다. 정답 풀이는 앞서 정답을 숨기고 생성·검수한 Terra TRAIN24의 원문을 그대로 사용한다. DEV의 새 풀이와 오류 문장은 학습 자료로 옮기지 않는다.

두 작성자가12개씩 만든 교정 초안을 서로 교차 검수했다. T17은 옳은 각도 주장을 틀렸다고 지적한 진단이어서 교정만 보류했다. 원래 초안과 불합격 근거를 보존하고, 두 학습군 모두 해당 교정 뷰를 동일한 정답 풀이로 대체한다. 최종 구성은 공통 정답 풀이24개·확정된 교정23개다. 이후에 학생이 스스로 수정한 오류의 국소 교정 예제는 그 사실을 표시하며 원래 최종 실패의 원인으로 단정하지 않는다.

## 학습과 평가 조건

같은 초기504개 언어 LoRA 텐서, 고정 기본 모델·비전 인코더, 학습 시드0, LR0.0001, 조건별30업데이트·120노출을 사용한다. 다섯 번의 같은 문항 순환 중0·2·4회차는 공통 질문만의 정답 풀이,1·3회차는 두 군에 같은 학생 오류 구간을 주는 입력이다. A는 검증된 조건에서 다시 풀고, B는 오류 이유·수정 지도를 붙인 뒤 A와 같은 재풀이를 학습한다. 감독 토큰 수·형식 차이를 기록하므로 B−A는 교정 레시피 전체의 효과다.

5스텝은 첫20개 공통 정답 예제 뒤여서 교정 개입 이전의 진단이다. 후보 선택에 사용하지 않고 최종30스텝 두 군을 모두 평가한다. 원문 질문만 받는 DEV에서 BASE 대비 취약 순증2/12 이상·안정군 신규 손실0을 요구한다. 통과 후보가 없으면 추가 시드와 학습 연장 없이 종료한다. 통과 후보 하나만 새 생성 시드31·32에서 순증 합계4/24 이상·각 시드1/12 이상·안정 신규 손실0으로 재검증한다.

선택된 후보의 BASE 대비 성능 확인과 B−A의 추가 효과 판정은 별개다. 선택 후보만 새 시드로 재검증하므로 B−A의 여러 시드 효과를 입증하는 설계는 아니다. 새 후보 두 개의 최초48응답은 수치 통과 여부와 무관하게 익명 단계 검수를 하되, 그 판정으로 실패한 후보를 재선택하지 않는다. CONF와 공식 평가는 계속 보호한다.

## 실행 검사와 기록

최초 BASE 생성24개는 봉인된 기존 실행과 응답 문자열·생성 토큰·입력 토큰이 모두 정확히 일치했다. 이후 첫 학습 시도는 입력 인코딩 검사에서 중단됐다. 모델 생성·옵티마이저 구성 전이어서 업데이트는0회였다. 이미지 텐서는 같았지만, 답변 길이와 함께 늘어나는 `mm_token_type_ids`까지 이미지 메타데이터로 취급한 비교식이 잘못된 중단 원인이었다.

이미지 픽셀·그리드 전체 일치는 유지하고, 토큰 메타데이터는 각 시퀀스 길이·공통 입력 구간 일치·답변 구간0값을 따로 검사하도록 수정했다. CPU에서 전체96뷰를 실제 인코딩해 통과했으며 최대639토큰으로 잘림은 없었다. 학습 데이터·라벨·순서·최적화 조건·성공 기준은 바꾸지 않았다. 이전 시도의 코드·등록·실패 기록과 BASE 출력은 `encoding_attempt1/`에 보존했다.

재등록 후 BASE를 새로 생성한 것으로 기록하지 않는다. 기존 BASE의24개 완전 일치와 동일한 평가 설정을 다시 검사하고, 원래 실행 시점의 등록·프로세스 메타데이터를 그대로 보존한 파생 권한 문서로 연결했다. 새 권한 문서는 기존 실제 생성이 재등록보다 먼저였다는 사실과 추가 생성0개를 명시한다.
