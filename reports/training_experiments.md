## 공통 설정

**지키는 규칙** (모든 실험)
- MMMU val은 학습에 쓰지 않습니다. 학습 데이터에서 MMMU val과 겹치는 문항(텍스트 정규화 일치, 5-gram 겹침, 이미지 해시)을 뺍니다(`scripts/audit_bmmr.py` 규칙).
- MMMU-Pro, MMMU test, 중국어 데이터는 쓰지 않습니다.
- 제출 모델에는 외부 레이어나 모듈이 없어야 합니다. LoRA는 병합해서 평가하고 제출합니다. 학습 중 교사나 판정 모델은 써도 됩니다.
- 정지 규칙과 판정 기준은 실행 전에 `v*_protocol.md`에 등록하고, 결과를 본 뒤에는 사용자 결정 없이 바꾸지 않습니다. 바꾼 경우 Amendment로 남깁니다.
- 좋은 seed를 고르지 않습니다. 개발 평가는 seed 0 하나로 하고, 5 seed는 최종 평가에만 씁니다.

**평가**
- **900문항 개발 평가** (§5.5, [improvement_strategy.md](improvement_strategy.md)): `SEEDS=0 bash eval.sh <병합 모델> runs/<이름>` → `analyze.py compare results/seed* vs runs/<이름>/seed0 --base-mean 1`. 판정: 95% CI 하한 > 0이면 강한 후보, 점추정 > 0이고 망각 신호가 없으면 후보, 그 외는 판정 보류.
- **216문항 진단** (v1–v5): base 5 seed에서 1–3번 맞힌 문항 216개(`grpo/data/ids_216.txt`)를 seed 5, 6으로 평가했습니다. 기준은 v1 r009(≈ base)의 37.5%입니다. 노이즈가 커서 v5 이후 900문항 평가로 바꿨습니다.

**학습** (v1–v6 공통)
- LoRA r16/α32(언어 모델 linear 층), vLLM으로 rollout(T=1, 8,192토큰), HF로 학습. clipped surrogate 0.2, base와의 k3 KL, token-mean loss, 최적화 스텝당 4그룹.
- 환경: RTX 4090 24GB, 62GB RAM. 라운드당 10~60분(문항 수, 판정 모델 사용 여부에 따라 다름).

**교훈**
- 외부에서 써 준 풀이로 SFT하면 모델 고유의 긴 풀이 방식이 무너지고, 학습한 문항을 외워도 새 문항으로 전이되지 않았습니다.
- 그래서 **모델이 스스로 생성한 답으로 학습하는 RL(GRPO)**로 넘어갔습니다. 정답 출처가 자기 생성이면 망각이 적다는 원칙에 따른 것입니다.
- 12문항 × seed 1개 수준의 평가로는 체크포인트를 고를 수 없었습니다. 이후 216문항 진단을 거쳐 900문항 평가로 바꿨습니다.

### 버전별 교훈

- **v1 → v2**: LR 1e-5에서는 LoRA가 거의 움직이지 않았습니다. 1e-4로 올리자 학습 문제 정답률은 올랐지만, K12 수준 객관식에서 배운 것이 MMMU로 옮겨 가지 않았습니다. 객관식이라는 형식이 같아도 전이되지 않았습니다. 잘림은 줄었습니다(106 vs 127–146).
- **v3**: 판정 모델 검증(Geometry3K DEV 120개 응답, 교사 판정과 비교)에서 Qwen 4B·8B와 Haiku는 탈락했고, Sonnet만 통과했습니다(수정된 기준). 과정 보상을 넣어도 MMMU는 그대로였습니다. 풀이 base에게 너무 쉬웠습니다(67%가 4/4).
- **v4**: 어려운 문항으로 바꾸자 잘린 답(0점)을 피하려고 **짧게 답하고 틀리는** 방향으로 학습됐습니다. 잘린 답에 0점을 주는 것, 오답에 주는 부분 점수, 너무 약한 KL(0.001)이 함께 원인이었습니다.
- **v5**: 잘린 답을 학습에서 빼자(DAPO의 overlong filtering) 길이 붕괴는 사라졌습니다. 하지만 900문항에서는 −1.5였습니다. 216 진단(2 seed × 216문항)은 잘린 답을 공식 파서가 우연히 맞히는 효과까지 섞여 있어 믿을 수 없었습니다.
- **v6**: 교사 증류는 안정적으로 동작했습니다(KL ≤ 0.025, 망각 없음, 길이 유지). 하지만 겨냥한 Business(74.8 → 74.7)와 Tech & Eng(55.0 → 52.9, r029)가 움직이지 않았습니다. 학습 문제에서 사라진 잘림은 MMMU에서 r029에 와서야 조금 줄었고(14.1 → 12.1%), 잘림이 잦은 160문항에서 잘림이 70.6 → 60.0%로 줄었지만 정답률은 39.4 → 37.5%로 오르지 않았습니다. 끝까지 쓰게 된 답이 정답이 되지 않았습니다. 교사(8B) 자체가 base보다 +3.4점 앞설 뿐이라, 증류로 얻을 수 있는 폭도 작습니다.
- **같은 분포의 안 본 문항 시험 (11/07, `grpo/heldout_protocol.md`)**: v2와 v6 모두 학습한 문항(각 100)과 안 본 문항(300 / 378)에서 정답률 변화가 없었습니다(v2 +1.5 / +0.17, v6 +2.5 / +1.65, 모든 CI가 0 포함). 바뀐 것은 길이와 잘림뿐이고(안 본 문항에서 잘림 v2 −2.7, v6 −3.1점, 유의), 줄어든 잘림은 정답으로 이어지지 않았습니다. 즉 MMMU에서 개선이 없던 이유는 데이터 분포(전이)만이 아니라, 학습이 같은 분포 안에서도 푸는 능력을 올리지 못한 데 있습니다.
- **RFT v7 (11/07–08, `grpo/v7_protocol.md`)**: base가 가끔 맞히는 문항에서 자기 정답 풀이만 골라 학습했습니다. 학습 손실은 0.46 → 0.42로 조금만 내려갔습니다(자기 답이라 처음부터 확률이 높음). 안 본 300문항에서 −1.58(CI 0 포함)로 관문 1을 통과하지 못했고, MMMU는 측정하지 않았습니다. 표본을 나눠 편향을 없앤 문항군 분석에서도 가끔 맞히던 문항 +3.1(CI −10.9 ~ +17.2), 늘 맞히던 문항 −0.7(CI −2.8 ~ +1.2)로 차이가 없었습니다. 학습한 문항(100)의 +7.5는 같은 표본으로 문항을 골라서 생긴 편향이 섞여 있어 근거로 쓰지 않습니다. 이 풀은 base에게 쉬워서(정답률 86%) 오를 여지도 작았습니다.
- **RFT v8 (11/08–09, `grpo/v8_protocol.md`)**: base 정답률 31%인 어려운 문항에서 데이터를 3배(3,101 풀이)로 늘렸지만, 학습 손실은 여전히 0.44 → 0.42로 거의 그대로였고 안 본 300문항 변화는 +1.00(CI 0 포함)이었습니다. 자기 풀이는 정답이든 오답이든 모델이 이미 비슷한 확률로 내는 문장이라, 정답 풀이만 따라 하게 해도 모델이 거의 바뀌지 않는 것으로 보입니다. 탐색 분석에서 base가 거의 못 풀던 문항군만 +3.3(CI +0.9 ~ +5.9)이었지만, 문항군 세 개 중 하나라 근거로 쓰지 않습니다. 사용자 결정으로 MMMU를 참고 평가한 결과 64.78(−0.38, CI −2.31 ~ +1.69)로 변화가 없었고, 늘 맞히던 문항(+1.32)과 잘림(14.1%)도 그대로였습니다(`v8_protocol.md` Amendment 1).
- **v6 운영**: 길이 정지 규칙이 잘린 답(8,192토큰)을 평균에 넣고 라운드마다 문항이 다른 점을 무시해서, 붕괴가 아닌데도 멈췄습니다. 같은 문항으로 짝지어 비교해 확인한 뒤, "끝까지 쓴 답 / 같은 문항의 교사 답 길이" 비율로 규칙을 바꿨습니다(`v6_protocol.md` Amendment 1).

## 4. 전체 교훈

1. **학습 문제에서 좋아진 것은 MMMU 향상의 근거가 아닙니다.** 여섯 번 모두 학습 문제는 좋아졌고, MMMU는 그대로였습니다.
2. **작은 진단 세트는 방향을 틀리게 알려 줄 수 있습니다.** 216문항 × 2 seed 진단은 v5에서 +3.5였는데 900문항에서는 −1.5였습니다. 단일 seed 900문항 평가도 +2.1점보다 작은 차이는 가르지 못합니다. 최종 판정은 5 seed로 합니다.
3. **잘린 답 처리가 학습을 좌우합니다.** 잘린 답에 0점을 주면 짧은 오답으로 무너집니다(v4). 학습에서 빼면 안정적입니다(v5, v6).
4. **LoRA RL은 안전하지만 지금까지는 효과가 없었습니다.** 900문항 평가 세 번 모두 늘 맞히던 문항을 잃지 않았습니다. 문제는 망각이 아니라 전이입니다.
5. **MMMU에서 틀리는 원인은 주로 지식과 그림 읽기입니다**([improvement_strategy.md](improvement_strategy.md)). 정답 보상 RL은 모델이 이미 가끔 맞히는 것을 더 자주 맞히게 할 뿐입니다. 다수결 기준 상한도 68.2(+3.2)이고, 그중 60%는 4/5 문항에 몰려 있습니다.
6. **정지 규칙은 같은 문항 기준으로 정의해야 합니다.** 라운드마다 문항이 바뀌므로, 길이나 정답률을 라운드 0과 그대로 비교하면 문항 차이를 학습 효과로 오인합니다(v5 정지, v6 오판).
