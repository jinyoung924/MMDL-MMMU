# Failure Tagging Protocol (v1)

실패 유형 태깅을 **누가 해도 같은 결과가 나오도록** 고정한 절차입니다. fine-tuning 전후에 같은 절차로 다시
태깅해야 "어떤 실패 유형이 줄었는가"를 비교할 수 있습니다.

## 1. 분석 단위

- **문항**을 단위로 합니다. 응답 한 개를 단위로 하지 않습니다. 같은 설정으로 N회(기본 5 seed) 실행한 뒤,
  - **안정 오답**: N회 모두 틀림 → *할 수 없음* (능력 문제). **태깅 대상.**
  - **불안정**: 1..N−1회 맞음 → *할 수 있는데 매번은 못 함* (행동/샘플링 문제). 별도 분석.
  - **안정 정답**: N회 모두 맞음.
- 태깅 자료는 `python analyze.py export results/seed* --out <DIR>`로 만듭니다. 문항마다 문제, 정답, 이미지 경로,
  메타데이터(과목·이미지 유형·난이도), 틀린 응답 2개가 한 파일에 들어갑니다.
- "어디서" 축(과목·이미지 유형·난이도)은 MMMU 메타데이터로 자동으로 붙습니다. 사람이 태깅하는 것은
  "어떻게" 축뿐입니다.

## 2. "어떻게" 축: 결정 트리

위에서부터 차례로 묻고, **처음으로 "예"가 나오는 곳이 그 문항의 태그**입니다.
태그 체계는 MMMU 논문(Yue et al., CVPR 2024, §5)의 오류 분류를 따르되, 이 모델에서 관찰된 G(생성 실패)와
PK(구분 불가)를 추가했습니다.

| 순서 | 질문 | 예 → 태그 |
|---|---|---|
| 1 | 보여준 응답 **모두** 최종 답을 쓰기 전에 잘렸나? | **G** 생성 실패 (하위: `loop` 같은 문장 반복 / `unfinished` 새 계산 진행 중) |
| 2 | 어느 응답이든 최종 답으로 **정답을 썼는데** 오답 처리됐나? | **S** 채점(추출) 오류 |
| 3 | 정답표가 틀렸거나, 문항이 주어진 정보로는 답할 수 없거나, 정답이 둘 이상 성립하나? (구체적 근거 필수, 애매하면 쓰지 않음) | **D** 문항 결함 |
| 4 | 이미지를 보라는 요청을 거부하거나 "이미지를 볼 수 없다"며 추측했나? | **X** 거부/포기 |
| 5 | 이하: 잘리지 않은 틀린 응답을 **처음부터 읽어** 정답에서 벗어나게 만든 **첫 번째 오류**를 찾는다. | |
| 5a | 첫 오류가 **이미지 내용을 잘못 읽은 것**인가? (숫자·글자·라벨·기호 오독, 없는 것을 있다고/있는 것을 없다고 함, 구조·대상 오인) — **이미지를 직접 열어 확인** | **P** 지각(perception) |
| 5b | 첫 오류가 **문제·선택지 텍스트를 잘못 읽은 것**인가? (NOT/EXCEPT 놓침, 조건 누락, 묻는 대상 착각) | **T** 텍스트 이해 |
| 5c | 첫 오류가 **틀린 사실·정의·공식·도메인 연관**인가? (이미지는 맞게 읽음) | **K** 지식 부족 |
| 5d | 이미지·텍스트·사실은 맞는데 **계산·논리·선택**이 틀렸나? (산술 오류, 공식 적용 오류, 맞게 구한 중간값을 번복, 자기 풀이와 다른 선택지 선택) | **R** 추론 |
| 5e | 전문 이미지(병리·영상 등)에서 모델의 묘사가 틀렸는지, 묘사는 맞는데 해석 지식이 틀렸는지 **태거가 판별할 수 없음** | **PK** 지각/지식 구분 불가 |

판정 규칙:
- **첫 오류 규칙**: 오류가 여러 개면 인과 사슬에서 가장 앞선 것 하나를 태그로 합니다. 이미지를 잘못 읽은 뒤 그
  위에서 올바르게 추론했다면 P입니다.
- **두 응답이 다른 유형으로 틀린 경우**: 완주한 응답을 우선합니다. 둘 다 완주했으면 더 이른 단계(P < T < K < R)의 오류를
  태그로 하고, `notes`에 다른 쪽을 적습니다.
- **P 판정은 반드시 이미지를 보고** 합니다. 응답만 읽고 "아마 오독했을 것"이라고 추정하지 않습니다.
- **확신도**: `high` = 증거가 명백함, `medium` = 합리적 추론, `low` = 추정. low가 많은 범주는 결과 해석에서 따로 표시합니다.

## 3. 출력 형식

문항당 JSON 한 줄:

```json
{"id": "validation_Music_3", "tag": "P", "subtype": "", "confidence": "high",
 "evidence": "모델 응답에서 첫 오류가 드러나는 문장 인용 (40단어 이내)",
 "truth": "이미지/사실이 실제로 무엇인지 (태거가 확인한 내용)",
 "notes": "두 응답의 차이, 부가 관찰 등"}
```

## 4. 신뢰도 점검

- 안정 오답 중 무작위 40문항을 **서로 독립인 두 태거**가 태깅하고 Cohen's κ를 보고합니다.
- 1차 태깅(v1)은 Claude 에이전트가 이 절차대로 수행했습니다. 두 번째 태거도 독립된 에이전트이므로 κ는
  "절차의 재현성"을 보여줄 뿐 사람 전문가와의 일치를 보장하지 않습니다. 팀원이 일부 문항을 직접 검수해
  사람-에이전트 일치도를 추가로 보고하는 것을 권장합니다.
