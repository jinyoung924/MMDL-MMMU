# 도표 풀이 SFT 파일럿 결과

## v1: 기존 공식 MMMU 평가

원래 train에서 검수한 19개로 학습하고, MMMU validation 900개 전체를 동일한 5개 seed로 평가했다.
학습 데이터와 분리한 외부 진단용 5개는 MMMU 점수에 포함하지 않는다.

| 모델 | 정확도 평균 ± seed 표준편차 |
|---|---|
| base | 64.93 ± 0.94% |
| answer | 50.76 ± 0.55% |
| rationale | 55.44 ± 0.53% |

| 비교 | 정확도 변화(%p) | 문항 bootstrap 95% 구간 |
|---|---|---|
| answer_vs_base | -14.18 | [-17.18, -11.22] |
| rationale_vs_base | -9.49 | [-11.51, -7.47] |
| rationale_vs_answer | +4.69 | [+2.00, +7.40] |

19개·학습 seed 1개인 작은 파일럿이다. 구간은 문항을 재표집한 값이며 학습 seed 변동을 포함하지 않는다.
두 SFT 조건은 같은 문항·정답·학습 순서·업데이트 수를 썼다. 풀이 조건은 정답만 조건보다 감독 토큰 수가 많다.
따라서 차이는 이 학습 설정에서 풀이를 포함한 효과이며, 시각 인코더의 병목 여부를 직접 증명하지 않는다.

## v2: 2026-10-29 소규모 SFT 선정 결과

**12개 checkpoint 모두 사전 학습 관문을 통과하지 못했다. 이번 조건에서 관찰한 최고
정답률은 기본 모델과 같은 87.5%였다. 개발 단계로 선정한 SFT 모델은 없다.** 아래 수치는
고정 학습 표본 40개, 학습 seed 0 / 생성 seed 0의 결과이며 공식 MMMU 점수가 아니다.

| SFT target | 학습률 | 5 step 정답/40 | 10 step 정답/40 | 20 step 정답/40 |
|---|---:|---:|---:|---:|
| 문단형 | 1e-5 | 35 | 34 | 32 |
| 항목형 | 1e-5 | 35 | 31 | 29 |
| 문단형 | 5e-5 | 32 | 32 | 27 |
| 항목형 | 5e-5 | 33 | 28 | 26 |

대조군은 **35/40 (87.5%)**다. 사전 기준 +10%p를 적용하면 최소 39/40이 필요했고,
이를 만족한 checkpoint는 0개다. 단지 기준이 높아서 탈락한 것에 그치지 않고, 이번
단일 seed에서 대조군보다 높은 점수 자체가 없었다. 다만 40문항·단일 학습/생성 seed의
관찰이므로 SFT 일반 또는 다른 주석·학습 설정의 효과가 없다고 결론내리지 않는다.

### 데이터와 실제 실행 범위

후보 657개에 자동 묶음 검사를 적용하고 135개에 이미지 기반 풀이 주석을 작성했다.
보호 자료와 연결된 12개, 정답 유일성에 문제가 있는 1개를 제외해 122개가 남았다.
그중 학습 80 / 잠금 확인 40 / 예비 2개를 고정했고, 기존 개발 40개를 별도로 유지했다.
당초 계획한 160/80/80을 확보한 것은 아니다. 모두 원래 BMMR train 출처다. 원래 평가
출처와 내부 개발·확인 자료를 SFT에 넣지 않았고, 동일·관련 문제 그룹을 역할별로 분리했다.
그룹 탐지는 자동 유사도와 수동 검토에 의존하므로 모든 의미적 중복의 부재를 보장하지는 않는다.

학생 정오를 보기 전에 역할과 학습 probe 40개를 고정했다. 오답 비율을 맞춰 추출하지 않았다.
학습 target은 **관찰한 표기와 대상 → 규칙 → 적용·계산·선택지 대조 → 최종 답**으로 작성했다.
주석은 현재 어시스턴트가 작성하고 이미지·계산·원본 답을 교차 확인했으며 독립 사람 정답
검수는 아니다. 검수 전 135개 TSV를 그대로 학습하지 않았고 잠근 train 80개만 인코딩했다.

각 조건은 새 기본 모델에서 시작해 80개를 한 번씩 사용했다. 시각 인코더를 고정하고,
LoRA rank16/alpha32, 누적 batch4, 20 step, 학습 seed0을 사용했다. 5/10/20 step은 각각
20/40/80개 노출 시점이다. 네 조건의 문제 순서는 같으며, 각 probe의 학습 노출 여부는
checkpoint 시점에 따라 다르다. target 토큰은 문단형 6,943개, 항목형 7,668개다.

두 target은 같은 사실·규칙·적용 문장을 사용하고 항목형에 제목만 추가했다. 따라서 서식과
추가 제목/토큰의 영향이 함께 들어가며, 기본 모델의 풀이 길이를 보존한 비교는 아니다.
원본 풀이를 동일 recipe로 학습한 대조군도 없어 새 주석 품질만의 효과를 분리하지 못한다.

### 추론 경로와 검증

BF16 base-weight 병합을 사용하지 않고 native LoRA로 평가했다. 대조군에는 A/B 행렬이
모두 0인 adapter를 사용해 학습 adapter와 요청 경로 및 40개 batch를 맞췄다. 기존 CoT
프롬프트와 생성 설정(최대8192, temperature0.7 등)을 유지했다. 이 pilot은 기존 Answer-tag
정규식으로 채점하되 무작위 fallback을 쓰지 않는다. 공식 파서·채점은 변경하지 않았다.
`run_eval.py`에는 native adapter 옵션만 추가했고 기본 실행 경로는 유지했다.

native 엔진 사용 여부에 따라 짧은 greedy 출력 8개 중 7개가 달라졌으므로, v1의 공식
64.93%를 이번의 직접 대조군으로 쓰지 않았다. native 엔진 내 adapter 없음과 zero adapter의
동일 8개 학습 입력 검사는 8/8 토큰열이 일치했다. 이는 전체 입력에서의 동등성 증명은 아니다.

선정 평가 종료 후, 실제 학습한 문단형·5e-5·20 step adapter를 같은 8개 학습 입력에서
Transformers/PEFT와 native vLLM으로 비교했다. greedy256 및 presence penalty1.5를 맞췄다.
토큰열은 4/8, 최종 답은 7/8이 일치했다. 질문117252906에서 PEFT는 정답D를 122토큰으로,
native는 오답C를 15토큰으로 생성했다. 따라서 nonzero adapter의 완전한 경로 동등성을
확인했다고 말할 수 없다. 이 검사는 모델 선정에 사용하지 않은 사후 엔지니어링 검사다.

그 한 문제에서 기본 모델 BF16 가중치는 그대로 두고, PEFT adapter 파라미터와 관련 연산
정밀도만 FP32에서 BF16으로 바꿨다. FP32의 정답D가 다시 재현됐고, BF16에서는 오답C로
바뀌면서 **native와 15개 출력 토큰이 모두 일치했다.** 네 조건의 저장 adapter 텐서504개씩은
모두 F32였다. 설치된 vLLM의 `lora_dtype=auto`는 base dtype인 BF16을 따른다. 0인 adapter는
이 정밀도 차이를 드러내지 못하므로 zero 검사만으로 충분하지 않았다.

이는 **선택된 한 사례에서 adapter 실행 정밀도 변경이 답을 바꾼다는 증거**다. 전체40개나
공식 MMMU 하락 중 기여율은 측정하지 않았다. 본 표는 배포할 native 경로의 관찰 성능이며,
학습 자체의 변화와 학습→추론 정밀도 변경의 기여를 분리한 표는 아니다.

adapter 없는 보조 baseline(train80+development40)은 시작 후 대조군을 zero adapter로
정한 시점에 중복 실행을 피하려고 중단했다. 완료 점수나 모델 선정에 사용하지 않았다.
개발40은 앞선 정보 제공 진단에도 사용한 자료다. **이번 SFT checkpoint의 개발 평가,
잠금 확인40의 예측·채점, 새 공식 MMMU 평가는 수행하지 않았다.** 사전 관문 실패에 따른
중단이며 평가 자료를 학습에 재사용하거나 기준을 완화하지 않았다.

데이터 보호 음성 대조 7개, 12개 checkpoint 해시와 동일 학습 순서 확인, 실행 코드 해시
대조가 통과했다. 저장된 **520개 응답(대조군40 + checkpoint12×40)**을 잠근 정답과 정규식으로
재채점하여 요약 점수·통과 판단·파일 해시를 확인했다. 정상 종료했으나 유효한 Answer 태그가
없는 응답 1개는 막대 높이를 오독해 “None of the above”를 답한 경우였다. 정답을 맞히고
형식만 어긴 사례는 아니었다.

### 관찰한 실패와 해석

기본 모델의 오답 5개 중 3개는 8192-token 제한에 걸렸다. 좌표·각도 번호를 잘못 연결한
뒤 계산을 반복하거나, 큐브의 공유 면을 일관되게 세지 못하는 사례가 있었다. 이 5개는
학습 도형 편의 표본의 오류이며 전체 MMMU 오류 비중이나 시각 인코더의 병목을 증명하지 않는다.

문단형·5e-5·20 step에서는 기존 오답 2개를 고쳤지만 새 오답 10개를 만들었다. 중앙 답변
길이는 대조군 532.5에서 75.5토큰으로 줄었다. 예를 들면 21,31,37을 읽고도 사다리꼴 면적의
곱셈을 틀려 899 대신 890을 답하거나, 1/4-inch 큐브 60개의 부피를 60 cubic inches로
답하며 단위 환산을 생략했다. 큰 삼각형 면적만 계산하고 요구한 넓이 비율을 구하지 않은
사례도 있었다. 항목형·5e-5·20 step 역시 중앙 길이100토큰, 정답26/40이었다.

짧아진 출력과 성능 하락이 함께 나타났지만 **길이 감소가 원인이라고 분리해 입증하지는
못했다.** 낮은 학습률에서도 길이 중앙값의 큰 축소 없이 점수가 낮아진 checkpoint가 있었다.
실제 계산·관계 적용·선택지 확인의 실패를 관찰했으며, 학습 손실 감소만으로 정확도 향상을
판단할 수 없었다. BF16 병합을 제거한 이번 경로에서도 낮은 점수가 나타났다는 사실은,
v1 전체 하락에서 병합이 기여한 비율을 알려주지는 않는다.

문항을 짝지어 재표집한 탐색적 bootstrap 구간은 `sft_analysis.json`에 기록했다. 최고
점수와 동률인 문단형5 step의 변화 구간은 [-7.5,+7.5]%p, 항목형5 step은 [-12.5,+12.5]%p다.
12개 checkpoint 비교에 대한 다중 비교 보정과 학습 seed 변동은 포함하지 않는다.

현재 결과로 전량 주석 확대나 공식 성능 향상을 정당화할 수 없다. 다음 검증에서는 먼저
동일 학습 자료·target·예산에서 adapter의 학습 forward와 native 추론 정밀도를 맞추는
조건을 대조해 정밀도 차이의 영향을 분리해야 한다. 이어 기본 풀이의 형식·길이를 유지하며
필요한 오류만 교정하는 target과 이번 짧은 target을 비교할 수 있다. 두 변경을 한 번에
적용하면 다시 원인이 섞인다. 이 추가 학습 실험들은 아직 실행하지 않았으며 성공을 보장하지 않는다.
